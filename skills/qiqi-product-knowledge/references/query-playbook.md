# 检索手册：检索式模板、分层策略与坑位（乐享 v2）

**权威源**：乐享空间 `21c227640aab4f95b55e8daa580fd5e6`（企企产品知识库 v2）

## 一、核心方法：`entry_list_children` 列条目 → 取正文

**永远不要按「模块」的粒度读**。新结构下**一条功能 = 一页**，命中即条目边界。

### 1. 主通道：列模块条目（零依赖、最稳）

```
entry_list_children(parent_id: "<模块文件夹 entry_id>", limit: 200)
→ [{ id: "<32位entry_id>", name: "[EX-002] 功能：员工借款单" }, …]
```
**name 自带条目码** → 一次调用同时拿到「条目码 + entry_id + 功能名」。

模块文件夹 entry_id 见 `kb-index.md` §三。

### 2. 取正文

```
entry_describe_ai_parse_content(entry_id)        ← 全文（AI 友好）
block_fetch_page(entry_id, render_mode="mdx")    ← 带 data-id，用于小节级引用
```

### 3. 按功能名搜（只知名字时）

```
search_kb_search  keyword: "员工借款单"  type: "doc"
→ 标题即带条目码（如「[EX-002] 功能：员工借款单」）
```

### 4. 按轴筛选（能力域 / 来源轴 / 生命周期）

**方式一：原生标签过滤（免费版唯一的结构化过滤手段）**

```
search_kb_search  tag_ids: ["<标签id>"]  type: "page"  space_id: "21c227640aab4f95b55e8daa580fd5e6"
→ 返回条目自带 tags: ["模块-EX","能力域-费用与成本","来源-S1","生命周期-现行"]
```

> ⚠️ **`tag_ids` 是并集（OR），不是交集（AND）**（2026-10-15 实测）：
> `["模块-EX"]` = **28 条**；`["模块-EX","来源-S1"]` = **407 条**（并集，非 28）。
> **故跨轴组合筛选（模块 + 来源 + 生命周期）不能用检索参数一次完成** ——
> 要么**客户端二次过滤**返回结果的 `tags` 字段，要么走方式二。

**方式二：索引页客户端过滤（推荐用于多轴组合）**

```
block_fetch_page(entry_id: "<IDX-00.2-EX>", render_mode: "markdown")
→ 每行形如：  - **EX-020**费用标准控制 ｜ 费用与成本 ｜ S1 帮助文档 ｜ 现行 ｜`<entry_id>`
```
> 索引页用**列表**而非表格：block API 对 `table` 有 **≤10 行**限制，大表无法通过
> `block_create_block_descendant` 写入（会报 `row_size gt_lte`）。

> ❌ **`filters.udf_values` 不可用** —— 本库为乐享**免费版**，不支持自定义属性（UDF）。

### 5. 按语义找（不确定叫什么）

```
search_kb_embedding_search  filters.keyword: "报销预算是怎么控制的"
                            space_id: "21c227640aab4f95b55e8daa580fd5e6"
→ 片段（无条目边界）→ 据此找条目名 → 回到 §1/§2 精确定位
```
**向量检索只用于「发现线索」，不能作为引用依据**。

### 6. 按年份/期次找迭代变更

```
entry_list_children(parent_id: "46c16955831d4cdeaf30813b5c49d49e")   # 03 变更档案
→ [CHG-2026-09] … ；条目自身的「⛭ 版本沿革」小节也已就地含历史
```

> ⚠️ **登记册（智能表格）不可用于 Agent 检索** —— 实测 `smartsheet_list_records`、
> `smartsheet_describe_record`、按视图、`lexiang_fetch(resource=record)` **四条路径均只返回
> record_id，读不到任何字段值**。登记册仅供人在 Web UI 查看/筛选。

## 二、分层策略（省 token 的关键）

| 层级 | 动作 | 成本 |
| --- | --- | --- |
| 0 | 查 `references/kb-index.md` 判断该进哪一层 | 极低 |
| 1 | 查 `references/routing-map.md` 锁定域码与条目码段 | 低 |
| 2 | `entry_list_children` 列模块条目 → 得 `条目码 + entry_id` | 低 |
| 3 | 读该**一个条目页**（一页仅 20–80 行） | 可控 |
| 4 | 需要跨模块对照时，才另开 `[MECH-M*]` 机制页 | 可控 |
| ✗ | 尝试整读某个「模块」 | **不存在这种页面了** |
| ✗ | 依赖登记册（智能表格）做检索 | **读不到字段值** |

## 三、引用格式

每条产品结论附引用，格式：**条目码 + 乐享 entry_id**，并摘录原文。

> 员工借款单支持直接生成报销单、支持跨组织借款。
> —— `[EX-002] 员工借款单 › 关键要点`（乐享 entry_id `1366a25d933e400c8f281fa8a93ebde8`）

- **条目码永不变**（改名不改码），是跨载体最稳定的锚点。
- 需要精确到小节/表格行时，附 `block_id`：`[EX-002] › block 4fe303fc09754be5a4399c46369ab68f`。
  （块级 `data-id` 经实测**在编辑后保持稳定**。）
- 摘录「关键要点」原文，**不要改写后再当原文引用**。
- 摘不出原文依据时写「**知识库未覆盖**」，并引 `[GOV-03]`，不要给近似内容充当依据。

**禁止**：只给页面名；引用 `05 素材与快照` 的分发件。

## 四、坑位

1. **登记册读不到值** —— 四条 MCP 路径均只回 `record_id`；登记册只供人在 Web UI 用。
2. **智能表格写入的 CellValue 形态** —— 文本字段必须 `{value:"..."}`，其他形态一律 `code 999`。
3. **block API 的表格行数上限 = 10** —— 大表无法通过 `block_create_block_descendant` 写入
   （报 `row_size gt_lte`）。索引页因此改用**列表**格式。
4. **`block_update_block` 的 `update_text.style` 必填** —— 漏传报 `code 51`。
5. **`entry_import_content_to_entry` 不在允许列表** —— 只能新建（`entry_import_content`）；
   改已有页面须用 block 级操作。
6. **`block_update_page` 的 `replace_content` 会拒绝改表格结构** —— 表结构变更需删块重建。
7. **标签名不能含「:」** —— 会被拒（`code 10400`）；用 `-` 分隔（`模块-PM`）。
7b. **`tag_ids` 是 OR 并集** —— 多标签传参**不会**做交集（见 §一.4）；跨轴组合筛选须客户端过滤。
7c. **免费版无 UDF** —— `filters.udf_values` 不可用；四轴只有原生标签一种载体。
7d. **`entry_set_entry_validity` 的 `time_range` 必须传 epoch 秒** —— 传 `"2026-11-30"`
   或 ISO 串报 `code 999`；**不要据此判为"免费版不支持有效期"**（实测四型均可用）。
7e. **`entry_delete_entry` 是隐藏高危工具** —— **可调用但不在 `search_tools` 清单里**。
   **禁止据 `search_tools` 无结果断言工具不存在**；能力判定须用一次性测试对象实测。
   该工具无二次确认、无批量，误传真实 ID 即造成删除（2026-10-15 已发生过一次）。
8. **`entry_describe_ai_parse_content` 对列表渲染不全** —— 校验页面内容请用
   `block_fetch_page(render_mode="markdown")` 或 `mdx`。
9. **时效**：内容覆盖至 **2026-09-14**。回答「现在最新是什么样」时须说明该截止点。
10. **冲突处理**：S1 帮助文档 ↔ S2 迭代说明冲突 → 取**发布日期较晚者**（见 `[GOV-02]`）。
11. **不要解析 `05 素材与快照` 下的单体文件** —— 免索引、不得作依据。
12. **覆盖度有限**：迭代发布说明中仅 14% 完全覆盖、69% 部分覆盖、17% 未覆盖。
    命中不了 ≠ 产品没有该能力 —— 先排除「公开文档外能力」（`[GOV-01]` §三），再写「知识库未覆盖」。
13. **生命周期轴**：实测 61 条「下线」变更**全部属子功能/入口/规则级别**，
    无一是整功能下线 → 664 条功能条目当前**无「已下线」**。判定某能力是否现行时，
    须查该条目的「版本沿革」及 `[CHG-DEPRECATED]`，而非只看生命周期轴。
14. **⚠️ 写入时字面星号必须转义** —— 正文含 IP 通配符（`*.*.*.*`）、公式（`数量*（1+允差）`）
    等**字面星号**时，乐享 Markdown 会当作强调标记吃掉。写入前须把非成对粗体的 `*`
    转义为 `\*`。详见 `[GOV-04]` §2.1。
15. **读页面用 `block_fetch_page`，不要用 `entry_describe_ai_parse_content`** —— 后者对
    列表/表格渲染不全（会静默丢失内容）；`block_fetch_page` 返回纯文本（非 JSON），
    解析时勿按 `.data.content` 读。
16. **远端文本与源文档比对时需归一** —— 乐享返回会多出转义与链接外壳：`\*`/`\>=`/`\{\}` 转义、
    裸 URL → `[url](url)`、中英间空格压缩、表格分隔行；未归一会产生大量假失配。

## 五、与运行时技能的分工

| 问题 | 用什么 |
| --- | --- |
| 产品「是什么 / 怎么做 / 什么规则 / 有哪些字段 / 哪年变的」 | 本技能，查乐享 v2 |
| 客户「当前数据是多少 / 这个租户启用了吗 / 权限如何」 | `qiqi-cli`、`qiqi-business-foundations`，查运行时 |
| 业务语义与事实判断口径（档案/单据阶段/状态语义） | `qiqi-business-foundations` |

知识库只提供产品定义，**不证明当前租户已启用、有权限或存在相应数据**。两者冲突时，租户现状以运行时为准，并在回答中说明差异。

问：企企的员工借款单支持哪些能力？

```
   → [EX-002] 功能：员工借款单   id=1366a25d933e400c8f281fa8a93ebde8
2) entry_describe_ai_parse_content(1366a25d933e400c8f281fa8a93ebde8)
   → 功能说明 / 主要操作 4 步 / 关键要点 4 条 / 关联 / 版本沿革
3) 作答：
   摘「主要操作」「关键要点」原文
   引用：[EX-002] 员工借款单（乐享 entry_id 1366a25d…）
   关联提示：[EX-015] 报销冲借款、[MECH-M1] 组织与多组织
```

问：某功能是哪年上线的？

```
1) 直接读该条目页的「⛭ 版本沿革」小节（已就地含历史）
2) 需要完整期次脉络时 → [IDX-00.5] 变更期次索引 → [CHG-<年>-<月>]
```

## 七、写入与删除高危约束

- **MCP 无批量删除条目能力**：仅 `entry_delete_entry`，无二次确认；该工具不在 `search_tools` 清单中，**禁止据 `search_tools` 无结果断言其不存在**，也禁止用于探测性调用。
- **批量导入 / 批量回写必须串行**，不得并发写同一页面或映射文件。
- **禁止把真实业务 ID 传入探测性调用** —— 能力探测只能用一次性测试对象，并事后核验目标仍存在。
